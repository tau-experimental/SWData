## Технический отчёт и план действий: Приём преамбулы MLS-63 в зашумлённом канале (BPSK, 31.25 бод)## 1. Ретроспектива и эволюция архитектуры (Что было сделано)
В процессе совместной отладки модели передатчик-канал-приёмник мы последовательно прошли через четыре ключевые архитектурные концепции:

   1. Дифференциальный приёмник на сырых сэмплах (Отброшен):
   * Реализация: Умножение текущего комплексного сэмпла на предыдущий сопряжённый (S[n] * conj(S[n-16])) до коррелятора для снятия DBPSK.
      * Результат: Полный отказ при SNR < +2 дБ.
      * Причина: Квадратичный рост шума (Noise × Noise). На минусовых SNR слабый полезный сигнал полностью тонул в продуктах перемножения шумов.
   2. Линейный секционированный коррелятор (MLS-31) (Отброшен):
   * Реализация: Разделение преамбулы на 4 независимых блока для борьбы с ионосферным доплеровским уширением (1–3 Гц), вычисление энергий блоков и их некогерентное сложение.
      * Результат: Рост ложного «пуза» (шумового подножия) на интервале преамбулы. Схема упёрлась в предел при SNR = 0 дБ.
      * Причина: Длина последовательности MLS-31 (база всего 496 сэмплов при 500 Гц) даёт теоретический Processing Gain лишь +14.9 дБ. Промежуточное взятие квадратов модулей в 4 блоках привело к детекторным потерям, из-за чего случайные выбросы шума сравнялись с истинным пиком.
   3. Дифференциальный приёмник на уровне интегралов чипов (Отброшен):
   * Реализация: Сначала когерентное сжатие чипа (16 сэмплов), затем дифференциальное перемножение комплексных отсчётов чипов и корреляция.
      * Результат: На чистом сигнале — сплошной «частокол» ложных пиков до потолка разрядной сетки, в шуме — слепота.
      * Причина: Математический остаток разбалансировки знаков шаблонов (свойства М-последовательностей), помноженный на гигантскую константу чистого пилот-тона, а также паразитный фазовый дребезг fixed-point округлений DDS.
   4. Линейный полнобазовый когерентный приёмник BPSK (Текущий успешный базис):
   * Реализация: Передатчик переведён на чистый абсолютный BPSK (модуляция фазы 0°/180° прямо знаками MLS). Приёмник — сплошной линейный когерентный интегратор по всей длине преамбулы без промежуточных нелинейных операций.
      * Результат: На чистом сигнале — идеальный ноль на пилоте и бритвенно-острый пик на финише преамбулы. На SNR = 0 дБ — уверенное превосходство над шумом. На SNR = -0.5 дБ — появление опасных ложных пиков-конкурентов, подошедших вплотную к истинному маркеру. Схема упёрлась в физический лимит базы сигнала.

## 2. Ключевая гипотеза на следующий сеанс
«Перенос и интеграция фильтра децимации внутрь 32-битного накопителя коррелятора без промежуточного fixed-point округления».

* Проблема текущей децимации (8 кГц → 500 Гц): При жестком снижении частоты дискретизации до буфера приёмника слабый полезный сигнал в условиях SNR = -6 дБ имеет амплитуду значительно ниже младшего значащего разряда (LSB) АЦП. Фильтр децимации, укладывая данные в int16_t, выполняет сдвиг вправо и безвозвратно округляет эти биты в ноль, искажая структуру MLS.
* Суть гипотезы: Мы повышаем частоту дискретизации входного буфера до 2000 Гц (децимация исходных 8 кГц всего в 4 раза вместо 16). Количество сэмплов на один чип (32 мс) увеличивается с 16 до 64. Полная база когерентного накопителя для MLS-63 расширяется до 4032 сэмплов.
* Физический эффект: Вся интеграция 64 сэмплов внутри чипа происходит в 32-битных регистрах (int32_t). Младшие доли сигналов на уровне шума не теряются при округлении, а накапливаются линейно. Шум усредняется гораздо глубже ($\sqrt{4032}$ вместо $\sqrt{1008}$), дисперсия выходной шумовой полки падает, а полезный пик получает дополнительные +6 дБ реального энергетического выигрыша (Processing Gain), что должно продавить порог обнаружения до целевых -6 дБ.

## Модуль детектора преамбулы (mls_detector.c)

#include "mls_config.h"
// Оригинальный биполярный шаблон MLS-63 (BPSK фазы 0/180 на передаче)static const int8_t MLS63_Original_Ref[MLS63_LEN] = {
    // 63 элемента: +1 или -1, строго соответствующие вашему передатчику
};
static cplx_i16 RingBuffer[RING_BUF_SIZE];static uint16_t BufPtr = 0;
void mls63_detector_init(void) {
    BufPtr = 0;
    for (int i = 0; i < RING_BUF_SIZE; i++) {
        RingBuffer[i].i = 0;
        RingBuffer[i].q = 0;
    }
}
/**
 * Полнобазовый когерентный BPSK коррелятор
 * Вызывается на каждый входящий сэмпл (новая частота: 2000 Гц)
 */uint32_t mls63_detector_process(int16_t in_i, int16_t in_q) 
{
    // Запись сэмпла напрямую в кольцевой буфер (без промежуточного округления)
    RingBuffer[BufPtr].i = in_i;
    RingBuffer[BufPtr].q = in_q;

    int32_t accum_i = 0;
    int32_t accum_q = 0;
    
    // Сплошной линейный когерентный интегратор по всей истории
    for (int c = 0; c < MLS63_LEN; c++) 
    {
        int8_t ref_sign = MLS63_Original_Ref[c];
        
        // Определение точного физического положения чипа в прошлом буфера
        int16_t chip_history_depth = (MLS63_LEN - c) * SAMPLES_PER_CHIP;
        uint16_t chip_start_ptr = (BufPtr - chip_history_depth + 1 + RING_BUF_SIZE) & RING_BUF_MASK;
        
        // Интегрирование сэмплов внутри чипа (накопление в 32 бита без потерь LSB)
        if (ref_sign > 0) {
            for (int s = 0; s < SAMPLES_PER_CHIP; s++) {
                uint16_t ptr = (chip_start_ptr + s) & RING_BUF_MASK;
                accum_i += RingBuffer[ptr].i;
                accum_q += RingBuffer[ptr].q;
            }
        } else {
            for (int s = 0; s < SAMPLES_PER_CHIP; s++) {
                uint16_t ptr = (chip_start_ptr + s) & RING_BUF_MASK;
                accum_i -= RingBuffer[ptr].i;
                accum_q -= RingBuffer[ptr].q;
            }
        }
    }
    
    // Вычисление энергии (квадрат модуля векторов)
    int64_t total_coherent_energy = ((int64_t)accum_i * accum_i) + ((int64_t)accum_q * accum_q);
    
    BufPtr = (BufPtr + 1) & RING_BUF_MASK;

    // ВНИМАНИЕ: Для SAMPLES_PER_CHIP = 64 сдвиг нужно скорректировать (например, >> 20 или >> 22),
    // чтобы уберечь uint32_t от переполнения при высоком SNR. Проверим на чистом сигнале.
    return (uint32_t)(total_coherent_energy >> 20); 
}

## 4. Пошаговый план действий на следующий сеанс## Шаг 2.1. Перестройка модели канала и передатчика

   1. Изменить коэффициент децимации в модели канала с 16 на 4 (выходная частота дискретизации для приёмника должна стать 2000 Гц вместо 500 Гц).
   2. Проверить, что передатчик генерирует чипы длительностью строго 64 сэмпла (при 2000 Гц это сохраняет длительность чипа 64 / 2000 = 32 мс и скорость 31.25 бод).
   3. Переписать старый КИХ-дециматор под int32 и посмотреть, что изменится - вдруг произойдёт чудо и потерявшиеся биты это как раз то, чего не хватало?
   4. Новый КИХ-дециматор СРАЗУ писать под int32. Новая вводная: в процессоре есть расширение M, но оно умеет только умножать (не делить).
   5. И ещё одна новая вводная: на самом деле, в процессоре есть ещё и расширение F (single-precision), но оно примитивное и может умножать-делить-складывать, сравнивать и вычислять квадратный корень. Осмыслить возможность применения такого недо-FPU для повышения динамики в расчётах типа оценки мощности (где надо возводить в квадрат огромные числа и получать ещё более гигантские результаты, ведь ВСЕ биты целочисленных результатов там нам не нужны - только старшие!).

## Шаг 2.2. Верификация «Чистым сигналом» (SNR = +96 дБ)

   1. Скомпилировать приёмник с параметрами SAMPLES_PER_CHIP = 64 и RING_BUF_SIZE = 4096.
   2. Подать идеальный BPSK-сигнал.
   3. Критерий успеха: Идеальный ноль на протяжении пилот-тона и одиночный бритвенно-острый пик на финише преамбулы. Настройка битового сдвига (>> 20...24) так, чтобы пик занимал около 70–80% от максимального диапазона uint32_t без срезания верхушки либо перевод под float.

## Шаг 2.3. Штурм глубокого шума (Стресс-тесты)
Последовательно прогнать систему по точкам SNR с контролем высоты ложных пиков:

   1. SNR = 0 дБ: Сравнить геометрический разрыв между истинным пиком и «лже-пиками» с результатом прошлого сеанса. Ожидается падение амплитуды травы минимум в 2 раза.
   2. SNR = -3 дБ: Проверка устойчивости.
   3. SNR = -6 дБ (Целевой рубеж): Фиксация отношения сигнал/шум на выходе коррелятора. Пик должен уверенно доминировать.
   4. SNR ниже -6 дБ: несбыточная мечта или реальность?

## Шаг 2.4. Проектирование автоматического триггера (CFAR)
Как только пик на -6 дБ будет аппаратно подтвержден, мы напишем алгоритм адаптивного порога (Constant False Alarm Rate):

* Скользящее окно оценки дисперсии шума позади текущей точки.
* Автоматическая фиксация кадра при превышении порога в X раз.
* Передача точного индекса сэмпла начала пакета для последующего демодулятора полезной нагрузки π/4-DQPSK.
